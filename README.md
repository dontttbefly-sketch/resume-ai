# 简历工作台

一个跑在本机的求职工作台，分三件事：

- **简历编辑**：左边填内容，右边实时看到 A4 成品，一键导出 PDF
- **岗位匹配**：粘贴招聘软件上的岗位描述，看匹配度、缺什么，并生成可以直接发出去的打招呼话术
- **岗位池**：实习僧抓下来的岗位按你的简历算匹配度排序（抓取见 `scripts/shixiseng/`，投递留人工）

数据只存在你自己电脑的浏览器里。简历编辑和岗位池断网也能用；岗位匹配要调用模型，所以需要配一个 API key（配一次就行）。

## 怎么启动

**方式一（推荐）**：在访达里双击本目录下的 `启动.command`，等浏览器自动打开。

**方式二**：打开「终端」，粘贴下面两行：

```bash
cd /Users/bottom_/WorkBuddy/2026-09-10-20-59-15/resume-ai
pnpm dev
```

启动后地址是 <http://localhost:5173>。要关掉服务，在终端按 `Control + C`。

> 第一次启动如果提示 `env: node: No such file or directory`，说明终端里找不到 Node。
> 在 `pnpm dev` 前面加一行：
> `export PATH="/Users/bottom_/.workbuddy/binaries/node/versions/22.22.2-2/bin:$PATH"`

顶部左侧的开关在「简历编辑」「岗位匹配」「岗位池」三个视图之间切换，当前在哪个视图会被记住。

- **改内容**：直接在左边输入框里打字，右边立刻同步，不用点保存
- **加一条经历**：点模块底部的「+ 添加一段工作经历」
- **调整顺序**：每条经历右上角的 ↑ ↓
- **删掉一条**：每条经历右上角的垃圾桶图标（会二次确认）
- **隐藏整个模块**：模块标题右边的小眼睛图标。隐藏只是不显示在简历上，内容会保留，随时可以恢复
- **职责要点**：每条要点一个输入框。按回车新增下一条；在空输入框里按回车删掉这一条；每行右侧也有 ↑ ↓ ✕
- **证件照**：基本信息里的「选择图片」，选完会自动裁成正方形并压缩后再存
- **档案切换器**：工具栏「简历 1 ▾ 2/3 ＋⎘✎🗑」，最多 3 份简历应对不同岗位，详见下方「多档案」
- **完成度**：右上角显示必填项填了多少。鼠标悬停可以看到具体缺哪些
- **载入一页版 / 载入完整版**：两个还原按钮，都从源码恢复，内容改乱了就点（会先二次确认）
  - **载入一页版** = 默认这份，为投简历精简到 A4 一页
  - **载入完整版** = 从 `邹康平简历.pdf` 逐条转录的原文，含全部经历，导出约 2 页。这是你的**全部经历备份**，任何时候点一下就能整份切回来

## 导出 PDF

点右上角「导出 PDF」，第一次会弹出**导出引导**（可勾选"不再提示"），然后打开浏览器的打印窗口。设置建议：

| 选项 | 选什么 |
|---|---|
| 目标 | 另存为 PDF |
| 纸张 | A4 |
| 边距 | **无**（页边距已由网页样式内置，选无才不会双重边距） |
| 缩放 | **100%** |
| 背景图形 | **勾选**（否则模块标题的蓝色下划线可能不打印） |
| **页眉和页脚** | **取消勾选** ← 关键！ |

**关于"水印"**：如果导出的 PDF 每页顶部有日期、底部有网址和页码，那是打印对话框里「页眉和页脚」默认勾选导致的（实测把页边距改成 0 也压不掉，浏览器不支持网页替你关闭）。在对话框里取消勾选一次，Chrome 会记住这个站点的偏好，之后导出默认就是干净的。引导弹窗就是提醒这件事的。

导出的 PDF 文字是可选中、可搜索的真文字，不是图片（招聘系统的关键词解析不受影响）。推荐用 Chrome，Safari 在打印设置上差异较多。

**内容超过一页也没问题**：每页都会正确带上 14mm 页边距，不会出现文字顶到纸边或凭空多出空白页。当前的实际情况：「载入一页版」导出 **1 页**，「载入完整版」导出 **2 页**。

## 多档案（最多 3 份简历）

工具栏上有档案切换器（`简历 1 ▾ 2/3 ＋ ⎘ ✎ 🗑`）：

- **新建**：切到一份空白简历，原档案内容保留；最多 3 份，满了要先删
- **复制**：把当前简历整份复制成新档案，适合"在一版基础上改出另一个岗位版本"
- **重命名 / 删除**：作用于当前档案；删除不可恢复（有二次确认），至少保留一份
- 每份档案独立保存（模块开关也是各自记忆），切换时即时恢复
- 「载入一页版 / 完整版 / 示例」「清空」只影响**当前档案**

## 作品二维码

「基本信息」里有**作品二维码**字段（证件照旁边），上传后显示在抬头右侧，与证件照并排：

- 显示尺寸 20mm 见方，实测从导出的 PDF 里可以正常扫码识别
- 默认简历已放好作品集二维码（`public/qrcode.svg`），扫码直达作品集网站
- 想换成自己的：编辑器里点「选择图片」传一张白底、方正的二维码图（别带圆角卡托，影响识别）

## 岗位匹配怎么用

1. 顶部切到「岗位匹配」
2. 把招聘软件上的岗位描述整段复制过来粘到左边（职位名 + 岗位职责 + 任职要求，越完整越准）
3. 点「分析匹配度」
4. 看完缺什么之后，点右上角「生成话术」，出三条不同角度的话术，点「复制」粘到招聘软件即可

不粘 JD 想先看效果，点「载入示例」会填一段示例岗位描述。

## 岗位池怎么用

岗位池的数据来自实习僧（只抓不投）。先在终端跑一次抓取：

```bash
./scripts/shixiseng/run.sh                 # 抓列表（默认深圳 · AI产品经理 · 3 页）
./scripts/shixiseng/run-detail.sh          # 可选：抓前 10 个详情页 JD，精筛更准
```

然后打开工作台的「岗位池」：

- 抓完的数据会自动出现在列表里，按**匹配度从高到低**排好
- 每张卡显示：分数、岗位名、公司、薪资/周期、缺哪些关键词；点箭头展开看完整命中明细
- 筛选：匹配度下限（不限/≥40/≥60/≥80）、标题必含词、标题排除词、只看已抓 JD
- 「看详情」= 把这条岗位送进「岗位匹配」，出完整分析和打招呼话术
- 卡片上的外链图标在浏览器打开岗位页 —— **投递请自己登录后手动点**，工具刻意不碰投递按钮

细节和反爬原理见 `scripts/shixiseng/README.md`。

### 匹配度是怎么算的

**纯本地算的，不调模型**，所以每次结果一样、也能解释：

1. 从岗位描述里找出它提到的技能和关键词（词典在 `src/data/jdLexicon.ts`，面向 AI / 产品岗，约 90 个词条）
2. 逐个到你的简历文本里找有没有对应表述
3. 按权重加权算命中率：核心词 3 分、重要词 2 分、加分词 1 分

标签上鼠标悬停可以看到**简历里命中的原句**，方便你确认是「我确实写过」而不是碰巧撞词。

匹配度只反映**字面覆盖**。实际做过但写得含糊的事会被算成缺失，所以看到缺失项先想想是不是没写清楚，而不是直接放弃这个岗位。

### 话术是怎么生成的

调模型生成，三个角度各一条：

| 角度 | 思路 |
|---|---|
| 能力对标 | 用简历里最贴合岗位要求的经历正面回应 |
| 成果说话 | 挑一个具体、可量化的成果展开 |
| 业务理解 | 先说一句你对这个岗位要解决什么问题的判断，再接上相关经验 |

提示词里写死了「只能引用简历里真实存在的内容，不许编造经历和数字」，所以话术里的每个数据都能在你简历里找到出处。生成完自己再读一遍，确认语气像你本人。

不满意就点「重新生成」，每次结果不一样。

### 配 API key（只需配一次）

1. 在项目根目录新建文件 `.env.local`（注意前面有个点）
2. 写入三行：

```
MINIMAX_API_KEY=你的密钥
MINIMAX_BASE_URL=https://api.minimaxi.com/v1
MINIMAX_MODEL=MiniMax-M3
```

3. 重启服务（终端里按 `Control + C` 停掉，再 `pnpm dev` 起来）

密钥只在开发服务器进程里用，**不会进入网页代码**：前端请求的是同源地址 `/api/llm`，由服务端转发时才注入密钥。`.env.local` 已写进 `.gitignore`，不会被提交。

换其他厂商也行，只要接口兼容 OpenAI 的 `/chat/completions`，改 `MINIMAX_BASE_URL` 和 `MINIMAX_MODEL` 两个值即可。

### 三个已知情况

- **生成要等 20~100 秒**：M3 是推理模型，会先思考再作答，思考过程关不掉（官方明确不支持关闭），只能等它想完。参数里传了 `reasoning_split` 把思考挪到独立字段，所以界面上看不到思考内容。简单问题不思考（秒回）；简历内容越长、思考越久，用现在这份真实简历实测约 **96 秒**。
- **每次生成消耗 3.5k~8k token**：思考也算 token。代码里额度给到 16000，留了两倍余量。
- **偶发连接被重置**：走代理/TUN 环境时，到模型服务的连接大约每 8 次会被重置一次（失败耗时固定在 5 秒左右，像是中间设备主动断链，和请求本身无关）。代理层已经做了自动重试（最多 3 次、退避 0.5s/1.5s），你这边感知不到，偶尔只会觉得"这次慢了点"。

## 数据存在哪

存在浏览器的 localStorage 里（简历键名 `resume-ai/resume`，岗位匹配数据单独存在 `resume-ai/jd`），每次改动都自动写入。

- 换浏览器或清理浏览器数据会丢失
- **清空缓存也不会丢内容**：源码里存着两份副本 —— `src/data/myResume.ts`（一页版，默认载入）、`src/data/myResumeFull.ts`（完整版，全部经历）。首次打开载入一页版，工具栏上两个「载入…」按钮可随时分别恢复
- 想备份/换电脑，可以用 DevTools 的 Application → Local Storage 把 `resume-ai/resume` 的值复制出来

## 一页版和完整版

同一份经历存了两版，工具栏上一键切换：

| | 载入一页版（默认） | 载入完整版 |
|---|---|---|
| 内容 | 保留项目经历 + AI 相关的职责与数字 | `邹康平简历.pdf` 逐条转录的全部经历 |
| 版块 | 抬头 / 个人优势 / 工作经历 / 项目经历 / 教育经历 / 技能 | 多一个「资格证书」；个人优势 7 条、蓝禾 10 个项目全在 |
| 导出 | **1 页** | **2 页** |
| 数据源 | `src/data/myResume.ts` | `src/data/myResumeFull.ts` |

一页版相比完整版**只做删减，没有新增任何事实**：个人优势 7 条 → 2 条（删掉纯软素质那条）；兴趣岛的课程开发与销售业绩；壁虎的流水账式罗列压到 2 条；「资格证书」模块并入技能行；抬头去掉与作品集重复的 GitHub 主页、网址去掉 `https://` 前缀（抬头右侧有证件照，可用宽度只有 596px，带前缀会折行）。

**所有硬数字都留着**：1000 工时 → 2 周、每 100 条 5 人日 → 0.5 人日、生成率 40% → 70%、客服每天省 10min、满意度 +1%、漏看率 −50%、售前管理层每天省 1h、500 人+ CRM、人效 +50%、浏览量 20000+、盈利 1w+、月活 2k、社群千人。

### 为什么能压进一页

三件事一起做才够，只做一件都差很远：

| 手段 | 省下 | 具体改了什么 |
|---|---|---|
| 内容取舍 | ≈ 700px | 见上面的删减清单 |
| 字号密排 | ≈ 300px | `src/index.css` 的 `@theme`：正文 10.5pt → **9.5pt**、行距 1.65 → **1.5**；模块标题 11pt → 10pt。纸质上仍是正常简历字号（单页简历普遍 9–10.5pt） |
| 版心放大 + 留白收紧 | ≈ 250px | 页边距 16mm → **14mm**；模块间距、条目间距、要点行距各收 1–4px |

效果：内容高从 **2751px** 降到 **1006px**，单页上限 **1016.6px**（= 297 − 14×2 mm），正好装下并留 10px 余量。右边的红色虚线标的是单页安全边界，超出时顶部会提示超出多少、约几页。

### 自己量页数（不用反复导出试）

工程里带了两条实测脚本：

```bash
# 实测内容高度 + 各模块占用 + 导出 PDF；加 --full 会先点一下「载入完整版」再测
node scripts/measure-print.mjs /tmp/one.pdf http://localhost:5173
node scripts/measure-print.mjs /tmp/full.pdf http://localhost:5173 --full

# 用 PyMuPDF 逐页量真实 PDF 的页数与四边距（校验 14mm 有没有生效）
python scripts/pdf-margins.py /tmp/one.pdf
```

`measure-print.mjs` 走 Chrome DevTools Protocol 的 `Page.printToPDF`。两个坑：`Chrome --headless --print-to-pdf` 在本机会卡死几分钟没输出；`Emulation.setEmulatedMedia({media:"print"})` 只改媒体查询、不做真实分页，量不出页数。

顺带一个容易量错的点：`useOverflow` 观察的是 `.paper-content`（内容包裹层），不是 `.resume-paper`（纸张有 `min-height: 297mm`，高度恒定测不出变化）。同理，用脚本量正文行高要看具体元素，`.paper-content` 继承的是纸张上的基准字号，不是正文的。

### 想改回宽松排版

改 `src/index.css` 的 `@theme`（`--text-body` / `--text-small` / `--text-heading`）和 `src/lib/units.ts` 的 `PAGE_PADDING_MM` 即可 —— 但一页版会立刻装不下，得同步删内容。

## 以后想加模块（比如「获奖经历」）

只要改一个文件：`src/data/sections.ts`，往 `SECTIONS` 数组里加一段配置即可。编辑器、预览、显示开关、完成度自检会全部自动支持，其他文件一行都不用改。

```ts
{
  key: "awards",
  label: "获奖经历",
  layout: "entries",          // header / entries / skill-list 三选一
  defaultVisible: true,
  entry: {
    itemNoun: "一项获奖",
    addable: true, removable: true, sortable: true,
    fields: [
      { key: "name",  label: "奖项名称", control: "text",  role: "primary",   colSpan: 2, required: true },
      { key: "date",  label: "获奖时间", control: "month", role: "date",      colSpan: 1 },
      { key: "level", label: "级别",     control: "text",  role: "secondary", colSpan: 1 },
      { key: "note",  label: "说明",     control: "textarea", role: "body",   colSpan: 2 },
    ],
  },
}
```

字段的 `role` 决定它在简历上的位置：

| role | 出现在哪 |
|---|---|
| `primary` | 主标题，加粗：学校名 / 公司名 / 项目名 |
| `secondary` | 副标题：职位 / 学历 / 担任角色 |
| `date` | 右对齐的日期 |
| `meta` | 灰色次要信息行 |
| `bullets` | 圆点要点列表 |
| `avatar` | 抬头右侧的证件照（只对 header 排版有效） |
| `body` | 普通段落 |

`control` 决定编辑器里用哪种输入方式：`text` / `textarea` / `month` / `tags`（逗号分隔标签）/ `bullets`（可增删的要点列表）/ `image`（选图片，自动压缩）。

## 想扩充关键词词典

岗位匹配认不认得某个技能，取决于 `src/data/jdLexicon.ts`。想加词就往对应分组里加一条：

```ts
{
  term: "用户增长",                        // 界面上显示这个名字
  aliases: ["增长", "ug", "user growth"],  // 在 JD 和你简历里可能出现的写法
  weight: 3,                              // 3 核心 / 2 重要 / 1 加分
  group: "product",                       // ai / product / data / delivery / ecom / soft
}
```

`aliases` 写得越全，命中越准。英文不区分大小写。

## 想改样式

- **改字号 / 行高 / 配色 / 字体**：`src/index.css` 顶部的 `@theme` 块
- **改简历上的排版**：`src/components/preview/SectionRenderer.tsx`
- **改 A4 页边距**：`src/index.css` 打印段里的 `@page { margin: 14mm }`（屏幕上的预览边距同时要改 `.resume-paper` 的 `padding` 和 `src/lib/units.ts` 里的 `PAGE_PADDING_MM`）

> ⚠️ 页边距**必须**做在 `@page margin` 上，不能只做在纸张的 `padding` 上。
> 做在 padding 上时，内容一旦超过一页，只有第 1 页顶部和最后一页底部有边距，
> 中间的页会顶到纸边。这是实测踩过的坑。
